# ARCHITECTURE.md: Real-Time Crypto News Aggregator

## 1. Project Overview
**Objective:** Build a high-throughput, real-time cryptocurrency news aggregator mirroring the terminal-style UI and instantaneous delivery of platforms like CryptoPanic.
**Core Mechanics:** The system ingests external news feeds via background workers, standardizes the payload, stores historical data in a relational database, pushes the "hot" feed to Redis, and broadcasts new items to clients via WebSockets.

## 2. Technology Stack
*   **Frontend:** Next.js (App Router), React, Tailwind CSS (Dark mode by default), Zustand (global state), Lucide React (icons).
*   **Backend API:** Next.js Server Components and API Routes.
*   **Real-time Layer:** Custom Node.js WebSocket Server + Redis (Pub/Sub and hot cache).
*   **Ingestion/Processing:** Python (Celery/Redis or pure async) for scraping, deduplication, and basic NLP (ticker extraction, sentiment tagging).
*   **Database:** PostgreSQL with Prisma ORM.

## 3. System Architecture & Data Flow

1.  **Ingestion Workers (Python):** Background scripts poll RSS feeds, Twitter APIs, and the CoinGecko API. 
2.  **Processing Pipeline:**
    *   **Deduplication:** Hash titles and URLs. Drop identical hashes.
    *   **Tagging:** Regex/NLP matches against a dictionary of top 500 crypto tickers (e.g., matching "Ethereum" or "Vitalik" to `$ETH`).
    *   **Scoring:** Assign a default base score.
3.  **Storage & Caching:**
    *   The worker inserts the structured `Post` object into **PostgreSQL** for permanent archiving.
    *   Simultaneously, the worker pushes the `Post` to a **Redis List** (capping at the 1000 most recent items for the hot feed) and publishes an event to a Redis Pub/Sub channel.
4.  **Delivery Gateway:**
    *   A **WebSocket Server** subscribes to the Redis Pub/Sub channel. When a new post arrives, it broadcasts the JSON payload to all connected frontend clients.
    *   Standard REST endpoints serve historical pagination and user settings.

## 4. Core Data Models (Prisma Schema Reference)

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Post {
  id           String       @id @default(uuid())
  title        String
  url          String       @unique
  sourceDomain String
  publishedAt  DateTime
  kind         String       // "news", "media", "blog"
  sentiment    String       // "bullish", "bearish", "neutral"
  instruments  Instrument[] // Relation to tagged coins
  votes        VoteData?
  createdAt    DateTime     @default(now())
}

model Instrument {
  id     String @id @default(uuid())
  ticker String @unique // e.g., "BTC"
  name   String // e.g., "Bitcoin"
  posts  Post[]
}

model VoteData {
  id        String @id @default(uuid())
  postId    String @unique
  post      Post   @relation(fields: [postId], references: [id])
  bullish   Int    @default(0)
  bearish   Int    @default(0)
  important Int    @default(0)
  toxic     Int    @default(0)
}
```

## 5. UI/UX Specifications
*   **Layout:** Three-column layout. 
    *   **Left Sidebar:** Filters (All, Hot, Rising, Bullish, Bearish) and Portfolio tracking.
    *   **Center Feed:** The dense, high-frequency terminal list. Rows must be highly compressed vertically. Columns: Time (HH:MM), Title, Source, Ticker tags, Sentiment voting buttons.
    *   **Right Sidebar:** Trending coins / CoinGecko price widget.
*   **Styling:** Monospaced fonts for numbers, dark slate backgrounds (`bg-slate-900`), neon accent colors for tickers (Green for Bullish, Red for Bearish).
